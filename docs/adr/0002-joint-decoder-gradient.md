# The decoder loss trains the encoder through the hint z_t

Supersedes ADR 0001 (two-stage training, no joint training).

The first full two-stage run (`runs/main-seed1-decoder`) showed that a JEPA trained alone found a shortcut. Its latent oscillates with a period of 10 tokens, which divides the horizon k = 20. The mean cosine between latents 5 tokens apart is −0.15; at 20 tokens apart it is 0.96. 93% of the variance within a document is this oscillation. VISReg asks for spread, and the prediction loss is blind to any component whose period divides k, so nothing in the JEPA objective rewards a latent for carrying content. Varying k or enlarging batches only changes which predictable code is cheapest (details and numbers: ticket 006).

So the JEPA stage now also takes `decoder_w × decoder token loss`. Its gradient reaches the encoder only through the block-start hint z_t, which rewards z_t for what the decoder's 32-token window lacks and the next k tokens need. The committed future in the hint is detached. A hindsight commit is chosen using the real future, and a gradient through it would train the predictor and encoder on information that does not exist at inference. The predictor is trained only by the commitment loss. z_t has read tokens up to the block start only, so the hint leaks no target token (`test_hint_z_t_does_not_see_its_block` runs the encoder; `test_build_block_hints_never_leaks_future` checks the indexing).

`decoder_w = 0` is ADR 0001's recipe exactly: the decoder never runs in the JEPA stage. It stays the default until a sweep picks a weight, so existing two-stage checkpoints load as what they are. The joint recipe is the preset `docs/experiments/joint-decoder.json` until then. The decoder stage stays, for the π-argmax-hint decoder ablation and for refitting a fresh decoder on a frozen encoder.

ADR 0001's objections still hold, and we accept them. The decoder sees hints that move while the encoder trains; that co-adaptation is now the point. The two losses need a weight, and a weight that is too high can make the encoder a plain language-model encoder, so the sweep checks that the JEPA terms still fall. A further risk: a z_t trained by the decoder can carry most of what the decoder needs, so the committed future may add little. `measure` reports this as `future_use` (`null − pi_argmax` cross-entropy), next to H4's `hint_use`.
